What each stage measures (Miles source, pinned commit 8e99947)

Rollout (trainer idle): perf/train_wait_time is an inverse timer: everything outside the trainer's train block. Minus the hand-off timers below, it is the rollout: 160 Harbor trials on the EC2 boxes, generating with SGLang on the same H200. It is set by the slowest trials (timeouts × concurrency), not by the GPU, and has nothing to do with the method, so its run-to-run differences are noise from which trials ran long.

Hand-off: sleep + wake_up (trainer and SGLang share the GPU via --colocate, so each frees its memory for the other), update_weights (push the new adapter to SGLang), save_model and data_preprocess.

Teacher pass (aux only, perf/teacher_log_probs_time): the Q adapter is swapped into the policy's LoRA slots and one forward-only pass runs over all 160 trajectories (~2.6 M tokens). It saves each micro-batch's final hidden states for AQ. Same model, same tokens, so it costs about one policy log-probs pass (1.03–1.07×; step 1's 1.29× includes first-time warm-up).

Policy log-probs (perf/log_probs_time): one forward-only pass of the current policy, no gradients, which gives log π(xt) of every generated token for the importance ratio, and in the aux run also AQ = Q(s,x) − Σa π(a|s)·Q(s,a) from the saved teacher states, computed inside this pass. The exact 248k-vocab baseline adds almost nothing: aux's log-probs pass is within 2% of vanilla's.

Actor train (perf/actor_train_time): the update itself. For every micro-batch: forward with grad, then backward, then one Adam step on the LoRA weights (one optimizer step per rollout). With --recompute-granularity full only each layer's input is kept, so the backward first re-runs the layer's forward. Per token that is forward + recomputed forward + backward. The base weights are frozen (LoRA), so the backward only computes input gradients (~1 forward's FLOPs) plus small LoRA weight gradients and attention's backward. That is ≈ 3 forward passes, and the measured ratio is 3.0× in both runs. Miles' own MFU uses the same 3× (perf.py: actor_train_tflops = 3 · fwd_flops / time), and log-probs and actor train both run at ~460–480 TFLOP/s, so the time ratio is the work ratio.

Advantages + swap: what is left of train: GRPO advantages (+ β·AQ) and the teacher adapter swap, a few seconds.
